# NeroTech privacy & telemetry disclosure

NeroTech includes anonymous error reporting so that crashes and bugs caused by the mod can be
found and fixed. It is **on by default** and **opt-out** (see
[How to opt out](#how-to-opt-out)). This page is the full disclosure required by CurseForge's
moderation rules for mods that use an external analytics/error service, and it documents how
the system is designed to comply with the GDPR (EU) and POPIA (South Africa).

> **Status:** NeroTech's own Sentry DSN is built into published jars, so reporting is live unless
> you opt out. A build with the DSN blanked (`NeroTechTelemetry.DSN`) sends **nothing**,
> regardless of the settings below.

## What is collected (error reporting)

When an error **caused by NeroTech code** occurs, a report is sent to
[Sentry](https://sentry.io) (hosted in the **EU** — `ingest.de.sentry.io`) containing:

- the stack trace of the error and the error message (file paths containing your
  operating-system account name are masked before sending),
- the NeroTech version, the loader (NeoForge / Forge / Fabric) and its version, the Minecraft
  version, and whether the game is a client or dedicated server,
- the operating system name/version and Java version,
- a couple of the mod's own configuration flags (e.g. whether the Fusion meltdown and
  per-player pollution attribution options are enabled), so a crash that only happens at
  non-default settings can be reproduced,
- the list of **other loaded mods** (their public ids and versions only), so a crash caused by
  a mod conflict can be identified,
- a random event ID generated by Sentry for the individual report.

Reports are de-duplicated and hard-capped at 10 events per game session.

## What is NOT collected

- **No IP address** is stored (`sendDefaultPii` is disabled; Sentry discards the sender IP).
- **No username, player UUID, or machine/host name.**
- **No world data, chat, coordinates, inventories, or gameplay analytics** of any kind.
- **No advertising or tracking identifiers** — there is no persistent ID linking reports from
  the same player or machine.
- Errors caused by other mods or by Minecraft itself are filtered out and never sent.

## How to opt out

Set the following in `config/nerotech.properties` (created on first launch):

```properties
telemetryEnabled=false
```

This is a client-local switch (not server-synced) and covers everything error reporting sends.
The switch is read once at startup, so the change takes effect on next launch; nothing is sent while disabled, and
nothing is ever sent before the config — and therefore your choice — has been loaded.

## Per-player pollution attribution (opt-in, off by default)

Separately from telemetry, NeroTech's **pollution** system is **regional and aggregate by
default and stores no player data**. A server may opt in to per-player attribution by setting
`pollutionPerPlayerAttribution=true`; only then does NeroTech store, in the world save:

- the **UUID** of the player who placed a machine (never their name), and a per-UUID pollution
  total with a last-updated day stamp.

This data is **minimised** (UUIDs only), **retention-pruned** after
`pollutionAttributionRetentionDays`, and registered with Neroland Core's shared data-erasure
hook — so a single erase request (or Core's inactivity sweep) purges a player's NeroTech data
alongside every other Neroland mod. With the option off (the default), none of this is stored.

## Optional machine operating charges (off by default)

A server running **NeroEconomy** may set `machineOperationChargeCost` above 0. Only then does a
newly placed machine record the **UUID** of the player who placed it (never their name), so its
processing machines can charge that owner per batch of operations. The UUID is passed to NeroEconomy
for the charge only, is never logged with an amount, and never leaves the server (it is stripped from
the block data sent to clients). It is erased by the same data-erasure hook as above: an erased
player's machines drop their owner and are no longer charged. The ledger entry for each charge is
NeroEconomy's and is covered by NeroEconomy's own privacy notice, export and erasure.

## Progression milestone records

NeroTech records four personal milestones (fusion online, first collision, remediated, grid scale) and
one quest hook as **player-scope progression gates in Neroland Core's store**, keyed by the UUID of the
machine's stored owner only — so only when a machine already has an owner under one of the two sections
above, and never for an owner who has opted out of attribution. The gates are records, gate nothing,
and the UUID is never logged, broadcast or put in a threshold event (world events name a region or a
machine type and dimension — since 0.6.0 no longer a block position). The rows are covered by Neroland
Core's privacy notice and erased through the same shared data-erasure hook.

## 0.8.0 "Offworld Industry": what the new content stores

0.8.0 adds **no store keyed by a player**. Everything new is world data, item data or short-lived memory:

- **Induction Charger** — charges energy items held or worn by players standing on or near the pad. It
  works by proximity only: players found in a charging pass are used in that moment and forgotten. The
  charger never records an owner (even when operating charges or attribution are on), saves no player
  data, and logs nothing about who it charged. Companions are charged through the same pad without any
  record of whose they are.
- **Deposits** — the Deep Core Drill's virtual deposits are **world data**, keyed by dimension and chunk.
  A record holds only how much is left, the capacity and when it was last drilled, and is removed once the
  deposit has recovered. No player, owner or name.
- **Milestones credited to the operator** — four new milestone records (first foundry pour, first quantum
  processor, first deposit tapped, gas-fed fusion ignition) go to the player operating the machine **at that
  moment**, and only while they are online and have not opted out of attribution. NeroTech keeps that
  player only in memory on the machine (never saved, cleared when the chunk unloads, dropped on erasure).
  The record itself is a player-scope progression gate in **Neroland Core's** progression store: a row of
  gate ids under the player's UUID, no names, positions or times. Core erases those rows on the same
  shared erase request that runs NeroTech's eraser, so one request clears both.
- **Machines, multiblocks and tanks** — the new machine families, Blast Foundry, Deep Core Drill, Process
  Tank, Heat Exchanger, Annunciator Panel and the fusion fuel tier save only machine state (progress,
  heat, tank contents, formed/size, channel). The placing player's UUID is recorded only under the two
  opt-in sections above, exactly as before; the Annunciator Panel and Induction Charger never record one.
- **Tools** — item data on the new tools holds only tool state: charge, mode, a fitted lens or filter, a
  scanner cooldown. A machine carried by the Arc Wrench keeps its contents and settings, but its owner
  UUID is removed before it is put on the item.
- **Pollution exposure** — severe regions give players standing in them brief Weakness and Hunger unless
  they wear a charged Filter Mask. This is computed on the spot from the regional (aggregate) pollution
  value; nothing about the exposed player is recorded. The pollution store is keyed by dimension and
  region, never by a player (unless per-player attribution is switched on, above).
- **NeroLink (link schema 2)** — the `nearby` section lists machines within 128 blocks of the asking
  player, in their dimension, only while they are online: type, state, alarms and levels, with **no
  coordinates and no owner**; machines are addressed by short-lived opaque handles. The `catalogue`
  section is public recipe data, identical for every player. `alarm` and `meltdown` events go only to
  online players in range (and a machine's recorded owner) and carry **no coordinates**. Handles, the
  action rate limit (10 per minute) and the alarm throttle are kept in memory only, cleared within a few
  seconds of logout and at once on an erase request.
- **Gallery sites** — `/nerotech gallery` (creative, operators only) remembers where each gallery was built
  so `gallery clear` and `gallery tour` work from anywhere inside it: **the dimension and the origin block
  only**, at most 16 rows (the oldest is dropped first), and `gallery clear` removes that site's row. It
  records nothing about who built or toured it. Machines the gallery places never record an owner or an
  operator and credit no milestone, trophy or statistic. The gallery's demo deposit writes nothing to the
  deposit store.
- **Logs** — nothing NeroTech logs at INFO or above contains a UUID, a player name, coordinates or text
  written by players.

## Legal basis and your rights (GDPR / POPIA)

Error reports are processed on the basis of **legitimate interest** (GDPR Art. 6(1)(f); POPIA
s11(1)(f)): keeping the mod functional and crash-free, using the minimum data necessary. They
are engineered to contain no directly identifying personal information, are stored in the EU,
and are retained only for Sentry's standard retention period before automatic deletion.

To exercise any data-subject right (access, deletion, objection), contact
**[info@neroland.co.za](mailto:info@neroland.co.za)** with the approximate date/time of the
crash so the matching event can be located and removed. Sentry acts as a data processor; see
the [Sentry privacy policy](https://sentry.io/privacy/) and
[data processing addendum](https://sentry.io/legal/dpa/).

## Changes to this policy

If a future version of NeroTech ever collects additional data, this page will be updated
**before** that version is released, the change will be called out in the changelog, and the
same opt-out (`telemetryEnabled = false`) will continue to cover everything error reporting
sends.
